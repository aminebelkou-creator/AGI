## 2. Quick start

**Requirements:** Python 3.10+ (tested with 3.12), `pip install markdown pillow`. Optional: Node.js (for Lighthouse), Google Chrome (for screenshots).

**Preview the site locally**

```bash
cd v2
python -m http.server 8080 --bind 127.0.0.1
# open http://127.0.0.1:8080/index.html
```

**Rebuild everything after a change**

```bash
cd v2
python _build/pages.py          # writes the 17 generated pages (incl. audiences.py)
python _build/journal.py        # writes journal/*.html, relinks journal.html
python _build/launch_assets.py  # K-12 photo slots, .htaccess, sitemap.xml, robots.txt
python _build/build.py          # stamps header, footer, SEO tags, font loading into every page
python _build/linkcheck.py      # must report 0 real broken links
python _build/prelaunch.py      # lists what is still placeholder / unconfirmed
```

Always run `build.py` **last**: it overwrites the header/footer blocks of every page.

## 4. How the build works

The site is **static HTML**. Pages come from three kinds of source:

| Kind | Files | Edit here |
|---|---|---|
| **Generated** | 17 pages: index, about, programs, program pages, student-life, policies, contact, privacy, terms, parents, founder-letter, teachers, professional, investors, our-story | `_build/pages.py`, `_build/audiences.py` |
| **Converted** (from the original design tool, now plain HTML) | admissions, k12, partnerships, connect, journal, journal-ccgi-partnership | the `.html` file directly |
| **Hand-written** | forms.html | the `.html` file directly |
| **Generated articles** | `journal/*.html` | `_build/journal.py` + `_build/article.tpl.html` (content comes from `data/export`) |

Every page contains marker blocks that `build.py` replaces on each run – **never edit inside them by hand**:

```html
<!--site:seo--> … <!--/site:seo-->         canonical, Open Graph, JSON-LD (home)
<!--site:header--> … <!--/site:header-->   skip link, header, menus
<!--site:footer--> … <!--/site:footer-->   footer, WhatsApp button
```

### Script reference (`v2/_build/`)

| Script | What it does |
|---|---|
| `pages.py` | Generates the content pages; helpers `page()`, `hero()`, `cta()`, `ph()` (photo slot), `testimonials()`, `program_page()`, `MAP`; loads `audiences.py` |
| `audiences.py` | Parents, founder's letter, teachers, professional, investors, our-story pages |
| `journal.py` | Builds `journal/<slug>.html` from the export; uses local images (`journal-images.json`); relinks `journal.html` |
| `build.py` | Stamps header/footer/SEO into every page, non-blocking fonts. **Menu, footer, `SITE_URL`, `OG_IMAGE` live here** |
| `launch_assets.py` | K-12 photo slots, `.htaccess` (performance + redirects), `redirects.csv`, `sitemap.xml`, `robots.txt` |
| `linkcheck.py` | Checks every internal link, image and anchor |
| `site_audit.py` | Titles, descriptions, h1, alt text, heading order, page weight |
| `content_audit.py` | Leftover placeholders, stale dates, facts consistent across pages, US spelling |
| `prelaunch.py` | Lists all placeholders and open checklist items; exits 1 until **READY FOR LAUNCH** |
| `webp.py` | Converts `assets/web/*.png|jpg` to WebP |
| `images.ps1`, `compress_journal_images.ps1` | Resize/compress images (Windows) |
| `journal_images.py` | Downloads article images from the old WordPress site (done: 123/128) |
| `export_docs.py` | Copies the founder's letter to `docs/founder-letter.md` |
| `convert_dc.py`, `relink.py` | One-time migration scripts (already run; kept for history) |
| `shots.ps1` | Headless Chrome screenshots for visual checks |
| `export_spec.py` | Writes `docs/website-content-spec.md` (design-neutral content spec) from the built pages |

## 5. Common tasks

### Change the menu or footer
Edit `NAV`, `PROGRAMS` or `footer()` in `_build/build.py`, then `python _build/build.py`.

### Edit text on a generated page
Find the text in `_build/pages.py` or `_build/audiences.py`, edit, then run `pages.py` and `build.py`. Bodies are Python f-strings: write literal braces as `{{ }}`.

### Edit a converted page (admissions, k12, partnerships, connect, journal)
Edit the `.html` file directly (outside the marker blocks), then run `build.py`.

### Add a real photo
1. Put the image in `v2/assets/web/` (landscape, at least 1600 px wide for wide slots) and run `python _build/webp.py`.
2. Replace the slot. In `pages.py`/`audiences.py` a slot looks like `{ph("home-classroom", "A multi-grade classroom…", "4/3", "wide")}`; replace it with
   `<figure class="photo wide" style="--ratio:4/3"><img src="assets/web/home-classroom.webp" alt="Describe the photo" loading="lazy"></figure>`.
   In `k12.html` replace the `<figure … data-placeholder="photo:k12-…">` element the same way.
3. Rebuild. `prelaunch.py` stops listing the slot once its `data-placeholder` is gone.

### Replace the sample testimonials
Edit `TESTIMONIALS` in `_build/pages.py` (real quotes, with written consent – see `docs/parent-stories-guide.md`) and change the output so it no longer adds `data-placeholder="testimonial:…"`.

### Confirm a fact
Assumed facts are wrapped as `{PH_TXT('key', 'text')}` (highlighted in gold on the page). When Julie confirms, replace with the final plain text, tick the item in `v2/LAUNCH-CHECKLIST.md` (`- [x]`), rebuild.

### Change fees, dates or contact details
These appear on several pages. Search all sources, e.g. `Select-String -Path v2\_build\*.py,v2\*.html -Pattern "2,600"`, update each, rebuild, then run `content_audit.py` to confirm consistency. Contact details: `build.py` (footer), `pages.py` (home, contact), `forms.html` (`CONFIG`).

### Add a journal article
Today articles come from `data/export`. For a new post either add it to the export JSON (title, slug, date, markdown) and run `journal.py`, or copy an existing `journal/*.html`, edit the content, and add a row to `journal.html`.

### Set the final domain
`SITE_URL` in `_build/build.py`, then run `launch_assets.py` and `build.py` (sitemap, canonical and Open Graph URLs update).

## 9. Placeholders and the launch checklist

Nothing assumed should reach launch unnoticed:

| Marker | Meaning |
|---|---|
| `data-placeholder="photo:ID"` | photo slot waiting for a real photo (labelled "Photo" on the page) |
| `data-placeholder="testimonial:ID"` | sample testimonial |
| `data-placeholder="team:ID"` | placeholder name in the team grid |
| `data-placeholder="fact:ID"` (`PH_TXT`) | assumed fact, highlighted in gold |

`v2/LAUNCH-CHECKLIST.md` lists every fact by owner (AGI, Anglia, legal, tech) in 11 sections. `prelaunch.py` counts markers + open checklist items and prints **NOT READY: N open items** until everything is resolved. ## 10. Deployment

The site is plain files – any web host works; `.htaccess` assumes **Apache** (e.g. shared hosting).

1. `python _build/prelaunch.py` → **READY FOR LAUNCH**.
2. Set `SITE_URL`, rebuild (`launch_assets.py`, `build.py`), run all checks.
3. Upload the **contents of `v2/`** to the web root, **except** `_build/`, `_legacy/`, `LAUNCH-CHECKLIST.md`, `.thumbnail`, `support.js`, `world-dots.js`, `journal-posts.json` (not needed by the published pages).
4. Test the redirects (a few old URLs), every form on a phone, and the WhatsApp button.
5. Google Search Console: add the site, submit `sitemap.xml`. Make sure the Google Business Profile has the same address and phone.
6. Keep the old WordPress site offline only after the redirects are verified.

## 15. Troubleshooting

| Problem | Fix |
|---|---|
| A page lost its header/footer | It is missing the `<!--site:header-->` / `<!--site:footer-->` markers; add them back and run `build.py` |
| Edits to a generated page disappeared | You edited the `.html`; edit `pages.py` / `audiences.py` instead |
| `KeyError`/`NameError` in `pages.py` after editing | Unescaped `{` `}` in an f-string – double them |
| Python patch "not found" on Windows | Files may use CRLF line endings; normalize with `.replace("\r\n", "\n")` before matching |
| Garbled accents in PowerShell output | `$env:PYTHONIOENCODING='utf-8'` before running Python |
| Fonts look unstyled with JavaScript off | Expected: fonts load via `<noscript>` fallback; system fonts are used briefly |
| Popup never shows again while testing | It shows once every 7 days: clear `agi-story-popup` from the browser's local storage |
| Map blank in headless screenshots | Google Maps embed needs a normal browser with network |

## 16. v3 – complete content from both sites (how it works)

v3 rebuilt the content of the site from a **live crawl of americangroup-international.com (148 items) and angliamorocco.org (36 items)**, so that no program, service, fact, calendar date, policy or event is lost. Plan: `docs/rebuild-plan-v3.md`.

### Pipeline (run from `v2/`)

```bash
powershell -File _build/crawl_sites.ps1     # 1. download every page of both sites -> data/crawl/{agi,anglia}/ (not in git)
python _build/inventory.py                  # 2. clean text (menus/sidebars removed), facts, coverage -> data/crawl/inventory.json, docs/content-inventory.csv
python _build/content_map.py                # 3. every source page -> destination page + action + reason -> docs/content-map.csv (181/181 mapped)
python _build/facts_build.py                # 4. first run only: fact register v2/_build/facts.json + claims register claims.json
python _build/pages.py                      # 5. generate pages (pages.py + audiences.py + content_pages.py + i18n_pages.py)
python _build/journal.py                    #    journal articles (export + crawl-only posts)
python _build/launch_assets.py              #    .htaccess (147 redirects from the content map), sitemap (139 URLs), robots.txt
python _build/build.py                      #    header/footer/SEO/language switch on every page – always last
python _build/coverage_gate.py              # 6. GATE: every source fact present on its page, or excluded with a reason
python _build/linkcheck.py ; python _build/site_audit.py ; python _build/prelaunch.py
python _build/julie_questions.py            # 7. docs/julie-questions.md from the registers
python _build/export_spec.py                #    docs/website-content-spec.md (all pages)
```

### Rules
- **Content map first.** A source page is never "forgotten": `docs/content-map.csv` gives each one a destination and an action (keep / merge / expand / translate / drop + reason). Generators take their sources from the map (`MAPPED(dest)`).
- **Coverage gate.** `coverage_gate.py --phase N` exits 1 until every fact (prices, dates, emails, phones, numbers) of the phase's sources is on the destination page. Deliberate omissions go in `docs/content-exclusions.csv` with a reason (privacy, copyright, outdated, third-party text, extraction artifact).
- **Registers.** `facts.json` (fees, dates, contacts, numbers, each with source and status) and `claims.json` (claims to verify). Status `to-confirm` items appear on pages as gold placeholders and in `docs/julie-questions.md`.
- **Full texts.** Policies, handbook, programs and services keep AGI's published text in full (`render()` in `content_pages.py`), with a source note.

### Languages
`fr/` and `ar/` pages come from `_build/i18n_pages.py`. In those pages, `./x.html` links to the same language and `x.html` to English (made `../x.html`). `build.py` adds the language switch (EN · FR · ع), `lang`/`dir`, translated menu labels (`T` dictionary) and `hreflang` links. Arabic uses `dir="rtl"` and Noto Naskh Arabic. Every translated page is marked `data-verify="translation-review:<lang>"` until a native speaker checks it.
